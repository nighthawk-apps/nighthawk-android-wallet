## 1. MUST-FIX before release

**1.1 Reorg callback deadlock (guaranteed on first reorg)** — `sync.rs:401` takes `drk.write()` for the whole cycle; `sync.rs:442-461` invokes `ReorgEventCallback::on_reorg` while that guard is still held. Kotlin's `onReorg` (`NativeDarkfiSynchronizer.kt:64-70`) synchronously calls `confirmedBalanceAtomic()`/`listTransactions()` → `lib.rs:757` `block_on(drk.read())` → waits on the writer that is waiting on the callback. Sync thread is dead forever. Fix: collect the `ReorgEvent`, `drop(drk_guard)`, then fire the callback (and don't hold `reorg_callback.lock()` across the call — same issue in `lib.rs:1107-1111`).

**1.2 Sending is impossible in the shipped LWD-only config** — `transactions.rs:249` `drk.transfer()` → `transfer.rs:41` `lookup_zkas` (`rpc.rs:533`) + `append_fee_call` → `get_tx_fee` (`money.rs:1294`), and `transactions.rs:350` `drk.simulate_tx` (`rpc.rs:519`), plus `dao.rs:204/240` `drk.broadcast_tx` — all go through `darkfid_daemon_request` (`rpc.rs:603`) which returns `RpcClientStopped` when `rpc_client` is `None`. Both apps pass `darkfidRpcUrl = null` (`DarkfiMobileFfiApi.kt:87`, `SDKSynchronizerLive.swift:198`). The zkas cache (`transactions.rs:241`) is only logged, never fed to drk. Fix: patch vendored drk to take zkas bincodes + fee from injectable providers (LWD `LookupZkas`/fee estimate), or require darkfid for spend paths and say so.

**1.3 `generate_new_address` creates non-recoverable keys** — `lib.rs:936` → `money.rs:144` `Keypair::random(&mut OsRng)`. Funds received on any generated address are lost on mnemonic restore (`bootstrap.rs:204-207` imports only the derived key). Fix: derive additional keys deterministically (`blake3(DERIVE_CONTEXT || index)` from the mnemonic seed) and re-import all indices on restore, or remove the method.

**1.4 Plaintext payment memos + recipient addresses on disk** — `sync.rs:1492-1531` write memo/recipient into `drk.cache.kvdb` trees `payment_memos`/`payment_recipients`; the cache is `kvdb_overlay::Database::open_default` (`lib.rs:106` in drk), unencrypted (unlike the sqlcipher wallet DB and the XChaCha-wrapped block cache). `transactions.rs:380` persists them *before* send, so failed sends also leak intent. Violates hard invariant 4. Fix: store in the sqlcipher wallet DB or wrap values with the `cache_key` XChaCha20-Poly1305 used in `block_cache.rs:27`.

**1.5 Broadcast timeout makes the tx permanently unretryable** — `transactions.rs:390-396` keeps the `SENT_PAYMENT_META` entry on "timeout"; the next attempt hits the idempotency check at `:340-348` and returns `Ok(tx_hash)` without sending or `mark_tx_spend`. Fix: track "confirmed submitted" separately from "pending"; remove pending on any error (the write lock already prevents concurrent duplicates).

**1.6 No transaction history is ever written** — no `put_tx_history_record` call anywhere in the crate; `broadcast_transfer` bypasses `drk.broadcast_tx`. `list_transactions` (`transactions.rs:506`) reads an always-empty table; `is_sent = status == "Broadcasted"` (`:510`) would also flip to false once drk marks `"Confirmed"`. Fix: call `drk.put_tx_history_record(&tx, "Broadcasted", None)` after a successful LWD send and update to `"Confirmed"` on detection in `process_compact_block`.

**1.7 Mesh identity is all-zero after `wipe()`** — `mesh/identity.rs:54-57` zeroizes `secret` and sets `epoch=0`; `mesh/engine.rs:197` `wipe()` then `start_mesh()` (`mesh/mod.rs:50`) re-enables with the zero key. Every wiped device shares one peer id and one X25519 static key (known to all) until `ID_ROTATE_MS` (6h). Fix: `identity = MeshIdentity::generate()` in `wipe()`/`set_mesh_on(true)`.

**1.8 Noise replay window advanced before authentication** — `mesh/session.rs:241-244` sets `recv_seq = seq` from the *unauthenticated* envelope, then decrypts. One forged `NoiseEnc` with `seq = u64::MAX` bricks the session (all real frames rejected as `Replay`). Fix: decrypt first, then commit `recv_seq`.

**1.9 darkirc over Tor cannot reach onion seeds via the in-process arti proxy** — `tor.rs:155` `TorClientConfig::default()` + `tor.rs:289` `connect()` with default `StreamPrefs`: `allow_onion_addrs` defaults to false, so `.onion` targets from `darkirc_daemon.rs:711-728` fail with onion-disabled (fail-closed but non-functional; Android uses this proxy via `AppTorCoordinator.kt:110`). Fix: `TorClientConfigBuilder` with `address_filter().allow_onion_addrs(true)` and `StreamPrefs::connect_to_onion_services(BoolOrAuto::Explicit(true))` (as `third_party/darkfi/src/net/transport/tor.rs:125` does). Also set explicit `storage.state_dir/cache_dir` under the app cache path — default project dirs are unlikely to resolve on Android/iOS.

**1.10 ~1 in 2048 generated wallet mnemonics are rejected by the wallet** — `mnemonic.rs:194-230` draws entropy in `[2^221, 2^242)`; values `< 2^231` encode to 21 words (own test at `lib.rs:1383` admits 21–22), but `lib.rs:574` requires exactly 22. Affected users cannot create/restore. Fix: loop in `make_seed` until 22 words, and validate via `mnemonic_decode` + `is_new_seed` instead of a word-count check.

**1.11 DM metadata sent in plaintext / incompatible with desktop darkirc** — `darkirc_daemon.rs:211-221, 614-618` only checks that `msg` looks base58; `channel` (recipient) and `nick` go on the public DAG unencrypted. Upstream encrypts all three (`bin/darkirc/src/irc/server.rs:527-547`), so desktop clients won't even recognise these DMs. Fix: encrypt `channel`/`nick` with the contact saltbox exactly as upstream `try_encrypt`, and replace the `looks_like_saltbox` heuristic with an explicit `is_encrypted` flag from the caller.

**1.12 Release profile is `opt-level = 0`** — `rust/Cargo.toml:10-13` (`opt-level = 0`, `lto = false`, `strip = "none"`). Halo2 proving and BFV/OMR at O0 are 10–50× slower; symbols shipped. Fix: `opt-level = 3`, `lto = "thin"`, `strip = "symbols"`, `panic = "unwind"` kept for the fences.

## 2. SHOULD-FIX soon

- `checkpoint.rs:127-156` — "authentication" compares server-supplied `state_root/block_hash` against the *same server's* `GetTreeState`; empty fields or a `GetTreeState` error skip the check entirely. Snapshot is trust-the-LWD. Fix: hard-fail on missing/mismatched root; ideally verify root against a second source or an embedded checkpoint list.
- `checkpoint.rs:169-174` — cursor set to `min(scan_cursor, birthday-1)`; if `checkpoint.height < birthday-1` the gap `(height, birthday-1]` is never appended (`clamp_scan_start` jumps to birthday) → wrong Merkle root at spend time. Fix: reject checkpoints with `height != birthday-1` or backfill the gap.
- `bootstrap.rs:200-202` — `ensure_default_money_key` returns early if any default key exists, so opening an existing DB with a *different* mnemonic silently uses the old key. Fix: compare derived pubkey with stored default; error on mismatch.
- `lib.rs:764-775` — `confirmed_balance_atomic` reports the sole non-DRK token balance as DRK when the wallet holds exactly one foreign token. Fix: return only `DARK_TOKEN_ID`.
- `lib.rs:176-179` + all handle methods — every error collapses to `NativeDrkUnavailable`; `InvalidAddress`, `InsufficientFunds`, `NetworkTimeout`, `CryptoError`, etc. are never emitted (Kotlin catches `WalletNotInitialized` that can't occur). DM crypto errors at `lib.rs:1197-1242` should be `CryptoError`.
- `sync.rs:2170-2181` — `redact_sync_error` misses IPv6, `.onion`, `socks5://`, `grpc://`, `ws(s)://`, and bare `host:port`; regex recompiled per call. Tracing logs (`bootstrap.rs:87-90, 136-140`) log raw `{e}` unredacted.
- `darkirc_daemon.rs:128-171` — `darkirc_outbound_slots` exposes connected peer URLs and `publish_outbound_slots` writes them to `outbound_slots.json` unencrypted in the datastore (hard invariant 6). Fix: expose only slot state, not URLs; don't persist.
- `darkirc_daemon.rs:543-547` — if `thread::spawn` fails, `DAEMON_STATUS` stays `STARTING` forever (all later starts rejected). Reset to `FAILED` in the error arm.
- `darkirc_daemon.rs:590-706` — no length bounds on `channel`/`nick`/`message` (upstream `MAX_MSG_LEN = 512`, `server.rs:68`); `log::error!` at `:656-660` emits channel+nick (DM recipient) at a level that ships in release.
- `darkirc_daemon.rs:299-306` — `LogcatWriter` re-emits every tracing level as `log::info!`, but release `android_logger` max is `Warn` → all tracing warn/error is silently dropped in release (and `net` WARN lines with peer addrs would appear in debug).
- `tor.rs:46-63` — TOCTOU between failed `compare_exchange` and `store(BOOTSTRAPPING)`; two concurrent starters spawn two proxies, second bind fails and flips state to `FAILED` mid-bootstrap. Use a single CAS loop. `handle_socks_conn` has no read timeout (localhost only, low risk).
- `mesh/fragment.rs:68-125` — per-fragment payload is only bounded by `MAX_PAYLOAD` (1 MiB); assembler can hold `128 × 256 × 1 MiB` before the completion check at `:106`. Fix: reject fragments `> FRAGMENT_CHUNK + FRAG_HDR` and track running size. Also `engine.rs:402-409` assembles fragments addressed to other peers before the recipient filter.
- `mesh/session.rs:404-411` — `evict_if_needed` LRU-evicts `Ready` sessions on unauthenticated HS1 floods (`MAX_SESSIONS = 8`). Never evict `Ready` for a pending handshake; rate-limit `NoiseHs` like `NoiseEnc`. Handshake is unauthenticated (MITM-able) and data phase is static-static (no forward secrecy) — document or add eph-derived session keys.
- `mesh/engine.rs:120-122, 545-548` — `inbound_stamps`, `sync_seen`, `sync_sent`, `inbound_events`, `events` are unbounded (spoofable 8-byte sender ids; `inbound_events` only drained while darkirc runs). Add caps/GC.
- `mesh/lwd_ctrl.rs:164-165` — `4 + el + 4` overflows `usize` on armeabi-v7a (32-bit target in `scripts/build-darkfi-mobile-ffi-android.sh:97`); release has no overflow checks → wrapped length passes and `bytes[4+el..8+el]` panics on attacker bytes. Use `checked_add`.
- `mesh/abi.rs` — `nh_mesh_pop_outbound`/`nh_mesh_pop_inbound_event` pop the frame *before* `copy_bytes` capacity check (`:15-25`) → frame lost on `-3`. Most `extern "C"` fns are not panic-fenced; a panic across `extern "C"` aborts the process and a panic under `engine().lock()` poisons the mesh permanently.
- `lib.rs:829, 855, 881` — `build_transfer`/`estimate_transfer_fee`/`broadcast_transfer` hold `drk.write()` across network round-trips and Halo2 proving (`estimate_transfer_fee` doesn't even use `drk`); conversely every handle call `block_on`s against the sync thread's cycle-long write lock (`sync.rs:401`, up to `MAX_SYNC_CYCLE_SECS = 600`) → UI stalls/ANR risk.
- `estimate_transfer_fee` (`transactions.rs:420-436`) is a hard-coded 0.05 DRK; `fee_atomic` in history is always 0 without darkfid (`:515-520`).
- `lib.rs:1156-1159` — `validate_darkfi_mnemonic` doesn't check the `is_new_seed` version prefix (no checksum → valid-word typos pass); `mnemonic.rs:28` derivation skips NFKD normalisation that `mnemonic_decode` input also lacks.
- UDL/ABI: `DarkfiWalletHandle::close()` (`lib.rs:1126`) is not in the UDL, so `set_lwd_splice(None)` is never reachable from Kotlin/Swift. `DrkBootstrapConfig` `Debug` prints `darkfid_rpc_url` unredacted (`lib.rs:228`). Doc mismatch on `strict_omr_only` default (`lib.rs:208` vs UDL:72).
- `block_cache.rs:139` — `end - start + 1` underflows if `end < start`. `lib.rs:713-714` cache key is unsalted `derive_key(wallet_pass)` (offline brute-force of weak passwords reveals block interest).

## 3. Verified OK

- RNG: all key/nonce material from `OsRng`/`thread_rng` (CSPRNG); no seeded RNG outside tests. DM crypto (`lib.rs:1192-1243`) matches upstream `ChaChaBox` `nonce||ct` format; random 24-byte XChaCha nonce; AEAD tag enforced; length-checked before slicing. `AeadEncryptedNote` used for OMR metadata with `OsRng`.
- Mnemonic/password: `DrkBootstrapConfig` `Debug` redacts mnemonic/pass; `zeroize_secrets` after bootstrap; intermediate seed bytes zeroized in `secret_key_from_mnemonic`; BIP39 chat mnemonic uses 128-bit entropy, `decode_chat_entropy` checks 12 words.
- No panics on untrusted bytes in `omr_envelope.rs`, `memo.rs::parse_omr_metadata_plaintext`, `mesh/packet.rs`, `mesh/gcs.rs`, `tor.rs` SOCKS parser (all length-checked before `try_into().unwrap()`), `bulk_session::decode_offer`, `checkpoint::assemble_checkpoint_chunks`.
- Tor fail-closed for the wallet: `DarkfiWalletHandle::new` waits for real bootstrap (`tor.rs:113`) and installs a process-wide SOCKS route (`lightwallet_client.rs:479`); status only reports connected after `create_bootstrapped` succeeds. darkirc Tor path uses `active_profiles=["socks5"]` + `mixed_profiles=["tor"]` only.
- Mesh ingest cap is lockstep with upstream: `drain_mesh_inbound` checks `MAX_MESH_EVENT_BLOB` (`darkirc_daemon.rs:252`) and `ingest_mesh_event` re-checks (`event_graph/mod.rs:2289`); `EVENT_INNER_MAX` (64 KiB) is stricter. LWD ctrl allowlist rejects bulk methods; `submit_lwd_ctrl`/bulk paths return `BulkDenied`.
- DAO: proposal plaintext is never logged; `has_plaintext_data` only exposes presence; `can_*` correctly derived from secret-key presence; bulla parse enforces 32 bytes.
- darkirc lifecycle: CAS state machine, fresh stop channel per start, `catch_unwind` around daemon thread resets status; callbacks wrapped in `catch_unwind`; `stop_darkirc` idempotent. Wire `Privmsg` layout is tested against the upstream encoding.
- Bounded caches: `SENT_SYNC_SCHEMES`/`SENT_PAYMENT_META` FIFO-capped at 10 000; mesh DAG cache capped (256 events / 256 KiB); dedup capped at 1000.
- UDL ↔ Rust: every UDL function/method/record/enum field has a matching export with matching types; `u64→i64` conversions saturate (`try_from(...).unwrap_or(i64::MAX)`), except the `as i64` casts in `tx_inspect.rs:74` which only matter above 2^63 atomic units.
